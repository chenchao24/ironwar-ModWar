# 机库卡顿优化记录 · 2026-09-06

> 改动前备份：`backup_hangar_opt/`（第一轮）、`backup_hangar_opt2/`（第二轮 UX 打磨前）——均已随迭代结束清理，本文档记录全部改动与数值

## 二轮 UX 打磨（同日，响应「首次切车仍慢 + 整屏闪动 + 面板重排」反馈）

1. **全屏遮罩 → 小型浮标**：`#hangar-loading` 改为悬浮坦克上方的胶囊指示器（spinner + 进度条 + 文案，pointer-events:none），不再整屏压暗闪动；
2. **首次切车分帧装载**（`_loadTankThenShow`）：构建(≈10ms) + `renderer.compile` → 每帧 `initTexture` 4 张（浮标显示进度百分比）→ 全部就绪后无缝换车。装载期间旧车保持展示、页面持续出帧，不再有 1-2s 整屏冻结；
3. **进机库流程**（`_enterHangarWithLoading`）：选中车已预热 → 直达；冷车 → 机库屏幕先立起（无展示车）+ 同款分帧装载；
4. **邻车预测预热**（`_startPrewarm` 增强）：当前车预热完成后自动**预建并预热左右邻车**——正常浏览节奏下，切车永远命中「已缓存+已预热」的秒切路径，浮标几乎不再出现（LRU 上限 4 台含邻车，显存受控）；
5. **面板只刷文字**（`ui.refreshHangar` 重写）：性能参数行池（6 行实车参数 key 序列各车一致 + 热成像/激光压制 2 行固定项）与属性条池 DOM 只建一次，切换仅更新 textContent 与条宽；`_refreshPreview` 内容不变跳过 innerHTML。实测切车前后 `#fh-real-spec` 首行节点身份不变。

实测（窗口最小化时以手动泵帧驱动，逻辑等价）：切到已预热车 0 帧等待秒切、无浮标；未预热车装载全程页面可动、进度条可见；面板节点跨切换保持同一 DOM；开战/回机库/往返切换无错误。

## 一、根因（无头浏览器实测数据）

卡顿**不在同步 JS**（切车同步逻辑仅 2-10ms），而在**渲染帧**：

| 操作 | 实测耗时 | 原因 |
|---|---|---|
| 切到未看过的车后首帧渲染 | **648ms** | 该车纹理首次上传 GPU + 材质 shader 编译 |
| 二次进入机库后首帧渲染 | 111ms | 车库灯光/阴影程序 + 少量纹理 |
| `_setupMenuShowcase`（clone+建 Tank） | 10.7ms | 几何体/材质克隆很便宜 |
| 首次进入机库（Garage 程序化构建） | ~1-2s（一次性） | canvas 贴图 ×20 + PMREM 环境烘焙 + 全套几何 |

旧逻辑每次切车都 `dispose()` 旧展示车再 `clone(true)` 新车 → GPU 纹理反复释放/重传 + shader 反复编译，这就是「每台车都卡一下、每次进库卡 2-3 秒」的来源。

## 二、优化措施（js/main.js）

1. **Garage 构建挪到初始加载画面**（`_load().then` 内）：一次性重活在「正在装载战场资源…」阶段完成，首次进机库不再有整段冻结（`_enterHangar` 保留兜底构建）。
2. **展示车缓存 + LRU**（`_ensureHangarTank` / `_parkShowcase`）：看过的展示车隐藏常驻（上限 4 台，超出淘汰最久未用的并释放显存），重切秒开（实测 **9ms**、零遮罩）。开战时缓存车只隐藏不销毁（`_startBattle` 改用 `_parkShowcase`）。
3. **分帧纹理预热**（`_startPrewarm` / `_collectTankTextures`）：对缓存展示车每帧 `renderer.initTexture` 上传 4 张纹理（WeakSet 去重），浏览机库期间后台完成并标记 `_prewarmed`；离开机库自动暂停、重进续跑。预热完成后切车连首帧上传都没有。
4. **载入遮罩兜底**（`_enterHangarWithLoading` / `_cycleHangar` 重写）：遇到未缓存/未预热的车，先画「载入机库…/载入坦克…」遮罩（双 rAF 保证先绘制），构建 + 手动 `renderer.render` 一次把纹理上传与 shader 编译**吃在遮罩下**再撤除——用户看到的是短 spinner，而不是画面冻结。已就绪的车直达不闪遮罩；`_hangarBusy` 防连点。

UI：`#hangar-loading` 全屏遮罩（暗底 + 琥珀 spinner + 文案，风格与游戏一致），`ui.showHangarLoading(on, text)` 驱动。

## 三、实测结果（优化后）

- 切回看过的车：**9ms 秒切、无遮罩**（原每次卡 2-3s）；
- 首次切新车：~1.9s 有 spinner 遮罩（不再是冻结画面）；预热完成后的再次切换零开销；
- 预热后台推进正常（离开机库暂停、重进续跑）；LRU 缓存稳定在上限 4 台；
- 开战/结算/重进机库全链路无运行时错误；遮罩视觉符合游戏风格。

## 四、显存说明

缓存的展示车纹理不再释放（这是秒切的代价），LRU 上限 4 台可控显存；被淘汰的车再次切回时走遮罩重建路径。若低端设备仍紧张，可将 `_ensureHangarTank` 中的上限 `4` 调小。
